# 散户情绪指数（dsh-sentiment-index）

题材热度 + 散户情绪双指数看板：以「板块成交额占全市场比重」为热度锚点，叠加东财小单资金拆分做散户提纯，输出 0~100 的题材热度指数与散户情绪指数；详情页价格-情绪-量能三栏联动，背离（钝化 / 衰竭）标记一眼可见。

## 入口与形态

- 左侧导航「散户情绪指数」页（`/sentiment`），PC 上下三区；容器 ≥1024px 左右分栏（42% 排行 + 58% 详情），640~1023px 密度增强堆叠，<640px 手机档列表 / 详情整页切换；
- `devices: ['pc', 'mobile']`：移动端装配层把插件页注册为顶层路由（首页金刚区插件入口进入），组件内按容器断点自适应，不 import 任何桌面专属模块。

## 指标口径

- **热度指数** = 成交占比分位 × 0.6 + 相对放量（当日额 ÷ 前 20 日均额）分位 × 0.2 + 换手分位 × 0.2；
- **散户情绪指数** = 小单净占比分位 × 0.4 + 成交占比分位 × 0.3 + 赚钱效应分位 × 0.3（赚钱效应 = 上涨家数占比与涨停占比分位再对半）；
- 因子先各自归一化为**该板块近 250 日历史分位**（最少 20 个样本，不足记 null）再加权；某因子当日缺席时其权重按比例摊给其余因子，**绝不把 null 当 0**；
- **背离两条**：收盘价创 5 日新低而情绪指数 ≥ 60（钝化）；情绪指数创 5 日新高而小单净额连续 3 日为负（衰竭）；
- 权重进 `constants.ts`（`HEAT_WEIGHTS` / `RETAIL_WEIGHTS`），标「试验性」，可回测后调整。

## 数据与口径边界（必读）

- **混合源架构（v1.1.0，2026-10-30 王总确认）**：东财行情域封禁窗口式反复，全链路单点不可接受 ——
  板块清单（行业 thshy / 概念 gn，含当日涨跌家数与净流入）/ 板块年 K（≈500 日，比东财更深）/
  当日快照全部走**同花顺**（dsh-mainline 跑了数月的既有链路）；东财只保留两个不可替代的点：
  **fflow 逐日小单拆分**（散户提纯核心，全网唯一）与**涨停 / 炸板 / 跌停池**；
  分母走宿主 fetchMarketTurnover（腾讯，与 THS 分子量级一致：板块合计 ≈ 两市 98.5%），
  东财指数日 K 为次选降级。东财封禁时**采集照常**：散户因子当日缺席（权重自动重分配），
  恢复后自动补历史；fflow 需要 THS→BK 名称映射（等值 / 剥罗马后缀 / 别名表，存 scan_meta 缓存），
  映射缺失的板块散户因子如实缺席（不猜）；
- **「散户」= 东财小单估算口径**，指数是题材情绪参考而非精确散户测量（UI 常驻标注）；情绪历史深度受 fflow 限制约 121 个交易日（2026-03-27 起），250 日档下前段留空属预期；
- **交易日 15:30 前的半日 bar 一律不入库**（分母裁掉当日、板块合并只留 ≤ 基准日、快照字段不写）——半日值一旦落库会永久污染分位序列；
- 涨跌家数 / 换手率是 clist 当日快照字段（历史不可回补，自安装起逐日累积）；板块内涨停数来自东财涨停池按行业归属聚合（首次采集回补近 30 个交易日，概念板块无行业映射恒缺席）；
- **东财通道（v1.3.0，2026-10-31）**：东财 push2 系 WAF 按「浏览器 TLS 指纹 + 东财域 Referer」双条件放行，`app:http`（reqwest）对 push2his / push2 / push2delay 整批拒连（实测 2026-10-31）——插件改走**宿主注入的 JSONP 桥**（宿主 4.32.0 `EM_JSONP_BRIDGE_INIT_SCRIPT`：隐藏 iframe 加载东财轻量页，桥在东财上下文内代发 `<script cb=…>`，postMessage 回传，协议见宿主 PLUGIN_API.md §5.5.1）；push2ex 池子未被风控波及，仍走 app:http。桥缺席（旧宿主 / 纯浏览器 / 移动端未注入）自动回退 app:http，行为不劣化；
- **散户因子自积累（v1.3.0）**：每天 1~2 个 `clist` 请求拉**全板块**当日主力/小单净额与净占比（push2 快照域），按交易日落库自建历史 —— 与 fflow 历史接口**互相独立**：fflow 全灭期间散户因子照常逐日累积（无 121 日回补，250 日分位窗口自安装日起算，样本 ≥20 日开始出值）；fflow 可用日两路合并、当日以快照值覆盖；
- 频率红线（2026-10-31 按上游实测收紧）：同花顺并发 ≤3 + 每请求 500ms 错峰，单板块失败不阻塞、失败清单可单板块重试；**东财 fflow 走串行慢车道** —— 前置轻量探测（封禁中整段跳过、0 次无效请求）+ 串行 1.2s 间隔 + 连拒熔断（首拒停 20s 等窗口自愈，连续 2 次连拒跳过剩余板块），对齐 dsh-mainline 实测的「间隔 ≥1s 正常、短时连发立刻拒连（停顿约 20s 恢复）」；**只在用户点击时触发，不轮询**。

## 存储（ctx.db 三张插件表）

| 表 | 形态 | 内容 |
| --- | --- | --- |
| `board_history` | 每板块一行，`days` json 列 | 关注板块 = THS 日 K + 东财 fflow + 快照字段的全量回补历史（≤420 日）；非关注行业板块 = 安装起每日追加的快照行（≤5 日） |
| `index_daily` | 每板块一行，`series` json 列 | 逐日双指数 + 因子原始值 + 分位（每次采集后全量重算；分位只依赖 ≤ 当日数据，历史行永不漂移） |
| `scan_meta` | 键值行 | 关注清单 / 板块清单缓存 / THS→BK 映射 / 沪深成交额序列 / 采集元信息（含失败清单与炸板、跌停池计数） |

> **与开发方案 §3 的实现差异**：方案把事实表 / 结果表设计成「板块 × 交易日」逐日一行；
> 实现改为每板块一行 + json 整列 —— `ctx.db` 没有批量插入，首扫「30 板块 × 420 日」
> 上万行逐条 IPC 不可接受（dsh-mainline 的既有结论）。表数量与方案一致，
> json 列仍可被 Agent 的 `db_query` 读取。

打开页面**不联网**，全部读 `ctx.db`；「采集更新」是唯一联网入口（首扫 ≈120 请求 / 日常增量 ≤10），可在采集中离开页面，完成走 `app:notify` 浮窗。

## 对外服务

`consume('sentiment:repo')` 可读同一份快照仓储（板块事实 / 分母序列 / 指数序列 / 关注清单），与 dsh-mainline 的 `mainline:repo` 同范式。

## 文件结构

```
plugins/dsh-sentiment-index/
├─ plugin.ts                 插件定义（devices 双端 + 菜单贡献点）
├─ constants.ts              全部常量（URL / 权重 / 阈值 / 文案）
├─ types.ts                  插件内类型
├─ ths-data.ts               同花顺取数层（清单 / 年K / 快照解析，主源）
├─ em-bridge.ts              东财 JSONP 桥传输层（隐藏 iframe + postMessage，桥缺席回退 http）
├─ em-data.ts                东财取数层（fflow 小单 + 四档快照 + 池子 + BK 映射）
├─ judge.ts                  指标纯函数（分位窗口 / 双指数合成 / 背离检测）
├─ storage.ts                ctx.db 三张表（水合 + upsert + 差分统计）
├─ scan.ts                   采集编排（五步流程 / 15:30 落定 / 失败补采）
├─ SentimentBoardView.vue    看板页（情绪条 + 排行 + 详情 + 关注管理 + 失败清单）
├─ SentimentDetailChart.vue  SVG 三栏联动图（拖动平移 / 滚轮缩放三栏同步）
└─ manifest.json             清单（id / 版本，与产物导出强校验）
```
