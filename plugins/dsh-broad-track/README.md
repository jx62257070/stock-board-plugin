# 宽基跟踪（dsh-broad-track）

安装包从 [GitHub Release](https://github.com/jx62257070/tauri-plugin/releases) 下载，文件名形如 `dsh-broad-track-<版本>.zip`（版本以 Release 页面为准）。

一句话：国家队（中央汇金 / 汇金资管 / 证金 / 梧桐树 / 国新等）在 A 股的主要动作是**申购宽基 ETF**而不是买个股 —— 本插件跟踪宽基 ETF 的流入流出（日频二级市场资金流 + 季频份额申赎 + 半年频持有人结构），用**披露锚点 + 报告期后净申购分摊**预估其持仓，并按「大跌 + 资金流入 + 成交异动」等资金流形态推定它的操作。

## 功能特性

- **宽基 ETF 清单**：14 只主流宽基 ETF（沪深300 × 4 / 上证50 × 2 / 中证500 × 3 / 中证1000 / 科创50 × 2 / 创业板 × 2），覆盖沪深两个市场；6 个宽基指数快照同行展示。
- **日频资金流跟踪**：逐只 ETF 的主力 / 超大单 / 大单 / 中单 / 小单净流入（东财 fflow），宽基口径合计与近 5 日趋势。
- **季频份额申赎**：定期报告的期间申购 / 赎回 / 期末总份额 / 期末净资产，精确刻画「谁在进出」。
- **国家队持仓预估**：预估份额 = 披露锚点 + 锚点后各季净申购 × 国家队占比；折合金额 = 预估份额 × 最新价。锚点可编辑、可按持有人结构一键推算。
- **操作信号推定**：由宽基等权涨跌幅、主力净流入、成交额异动合成「强买入 / 买入 / 观察 / 撤退」四档，附触发依据与近 20 日信号时间线。
- **数据本地留存**：日频 / 季度 / 持有人 / 锚点四张本地表，再进页面只读本地快照渲染、零联网。

## 安装

前置：已安装 **[WHF 股票看板](https://github.com/WHF293/whf-stock-board)**。

1. 打开应用，进入「插件工坊」（应用内的插件管理入口）；
2. 选择「导入插件」，选中刚下载的 zip 安装包；
3. 导入后启用，左侧导航会出现「宽基跟踪」。

卸载：在「插件工坊」里对该插件点卸载，应用会询问是否一并删除本地数据表。

## 快速上手

1. 首次进入是空态 —— 点「**刷新日频**」拉取宽基 ETF 的资金流与行情（行情批量 1 次 + 逐 ETF 资金流与日 K 各 14 次，约 29 次串行请求）；
2. 再点「**同步季度**」拉取份额申赎与持有人结构（28 次串行请求）—— 这两份是持仓预估的输入；
3. 持仓预估卡给出宽基口径合计的预估持仓与较锚点变动；点「编辑锚点」可校正锚点（按定期报告披露）或一键按持有人结构推算；
4. 操作信号卡给出当前档位、触发依据与近 20 日信号时间线；
5. 明细表逐只展示最新价 / 涨跌幅 / 成交额 / 当日与近 5 日主力净流入 / 期末份额 / 季净申购 / 净资产 / 预估持仓。

## 配置项

| 配置名 | 说明 | 默认值 | 修改位置 |
| --- | --- | --- | --- |
| 国家队占机构持仓比例 | 持仓预估模型的分摊系数：机构持仓里国家队（汇金 / 证金 / 梧桐树 / 国新等）的占比 | 0.8 | 应用顶栏齿轮 → 插件设置 → 宽基跟踪设置 |
| 持仓锚点 | 每只 ETF 的锚点份额 / 报告期 / 来源；预估的起点 | 未配置时按持有人结构粗估 | 插件页面「持仓预估」卡的「编辑锚点」 |

## 数据与隐私

- **数据来源**：东方财富与新浪 —— 行情快照与每日资金流（`push2delay.eastmoney.com`）、季度份额申赎与持有人结构（`fundf10.eastmoney.com` F10）、日 K 成交量（`quotes.sina.cn`，仅用于估算成交额历史）。全部请求**串行**并留间隔（同上游 600 ms），原地小步重试兜底。
- **联网时机**：**只由你点击触发**（「刷新日频」/「同步季度」/ 锚点相关操作），不轮询。
- **本地存储**：结构化数据落在插件的四张本地数据表 —— `plugin_dsh_broad_track_etf_daily`（日频资金流与行情）、`plugin_dsh_broad_track_etf_quarter`（季度份额申赎）、`plugin_dsh_broad_track_etf_holders`（持有人结构）、`plugin_dsh_broad_track_anchor`（持仓锚点）。
- **卸载影响**：卸载时应用会询问是否一并删除这些表；**插件 id 一个字都不能改** —— 改了就等于换了一批新表，历史数据全部失联。

## 数据源与口径（2026-10-24 实测）

| 数据 | 端点 | 频率 |
| --- | --- | --- |
| ETF / 指数行情快照 | `push2delay.eastmoney.com/api/qt/ulist.np/get` | 实时（点击时） |
| ETF 每日资金流 | `push2delay.eastmoney.com/api/qt/stock/fflow/daykline/get` | 日 |
| 季度份额申赎 | `fundf10.eastmoney.com/FundArchivesDatas.aspx?type=gmbd&mode=0` | 季 |
| 持有人结构 | 同上 `type=cyrjg` | 半年 |
| 日 K 成交量 | `quotes.sina.cn/cn/api/json_v2.php/CN_MarketDataService.getKLineData` | 日 |

- **成交额历史**：东财 K 线在 push2delay 上不可用（rc=102），同花顺 line 对 ETF 404；用新浪日 K 的「成交量 × 收盘价」近似，并以当日东财精确成交额单点校准（校准因子应用到全部历史日）。
- **宽基涨跌口径**：信号判定用**跟踪 ETF 的等权平均涨跌幅**（时间线上没有指数日频数据，当前指数快照只做页头展示，两个口径不混用）。
- **份额日频不可得**：公开渠道没有 ETF 每日份额历史，故「流入流出」的日频信号用二级市场资金流，精确的申赎流入流出用季度报告口径。

## 已知限制

- **定位声明**：只做资金流痕迹的归类与持仓粗估，**不含任何买卖指令**；国家队没有公开每日持仓，预估与真实持仓必然有偏差。
- **分摊模型的粗糙处**：净赎回季按机构占比同比例分摊（国家队未必同比例赎回）；联接基金 / 险资的申赎也被计入分母。定期报告披露后应以披露数据校正锚点。
- **信号是推定不是公告**：「强买入 / 撤退」只是二级市场资金流形态与指数走势的合成归类，不等同于官方动作。
- **成交额近似误差**：历史成交额为「成交量 × 收盘价」的校准近似，与交易所口径有百分之几差距，只用于异动倍数（比值）判定。
- **上游限速**：东财会掐连接（`fetch failed`），取数层已做原地小步重试；连续失败时按单只 ETF 降级并推告警，不影响其余数据落库。

## 设计说明

**为什么是「锚点 + 净申购分摊」而不是直接加总份额？** 国家队的持仓没有每日公开值，但它的动作有两个可观测出口：定期报告的前十大持有人 / 披露整理（锚点），以及报告期间宽基 ETF 的份额申赎（净申购）。把净申购按「机构持有比例 × 国家队占比」分摊到锚点上，就得到一条随季报滚动、口径透明、可手工校正的持仓曲线。所有输入（锚点份额、机构占比、国家队占比、净申购）都在页面上直出，不做黑箱打分。
